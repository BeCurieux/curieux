Where each generator's method will come from is wired in code:
`src/content/methodology.ts` lists the asset ids per module and marks every
module **interim** until its source is converted. The studio shows "Interim
method" on those modules, and every generation records which method version
produced it, so outputs made before a conversion can be found and
regenerated. A test fails if a module claims `source` status while citing an
asset not marked `source_reviewed`.

## 3. Duplication and consolidation (method, pending source)

The addendum names seven overlaps. Without the documents we can't say what
overlaps or which version is better, so this is the procedure and the
proposed outcome to test, not a finding.

| Overlap                                           | Proposed single authority                                            | What to check in the documents                                                               |
| ------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Income Fit Test ↔ Income Fit Report               | Test = questions and scoring; Report = interpretation of each result | That the report's scoring matches the test's exactly; keep the report's narrative per result |
| Business Starter System ↔ Your Little Offer Kit   | Offer Kit owns the offer method; Starter System links to it          | Whether the two describe the offer steps differently                                         |
| Business Starter System ↔ Price It Right          | Price It Right owns pricing formulas                                 | Formula differences; keep worked examples from both                                          |
| Business Starter System ↔ First 5 Customers       | First 5 Customers owns early-customer outreach                       | Repeated scripts; consent rules for outreach                                                 |
| Faceless Content System ↔ 100 Faceless Hooks      | Hooks become one tagged library; the System references it            | Duplicate hooks; hooks containing income claims                                              |
| Faceless Content System ↔ 30-Day Plan             | The plan becomes the calendar template; the System explains it       | Whether the two plans differ                                                                 |
| Money & Operations Kit ↔ Side Income Money System | One Money Calculator with one set of formulas                        | Formula differences; country-specific tax content                                            |

Rule for every pair: the source files are never edited or deleted. The
consolidated version lives in the software, with a note of which document
and section each part came from. Distinctive material (worked examples,
stories, the founder's voice) is kept, not averaged away.

## 4. Research and legal-review flags

These apply by category and will be refined per asset:

- **Earnings and income claims** (FIT, opportunity cards, money tools, hooks):
  in the US (FTC) and Australia (ACCC) earnings claims must be substantiated
  and typical. Empire Studio's claims guard already blocks income claims in
  generated copy; converted FIT content needs the same review.
- **Tax, registration and consumer law** (five-country guidance, money
  tools, policy templates): must be dated, country-specific, framed as
  general information, and reviewed by someone qualified in each country.
- **Platform facts** (fees, Shopify settings, Etsy rules, Reels features):
  change often; store with a source and a review date and re-check before
  reuse.
- **Email and outreach** (First 5 Customers): consent rules differ (CAN-SPAM,
  Australia's Spam Act, UK PECR / GDPR).
- **Statistics anywhere**: keep the source, the date, and any caveat with the
  number, in the structured data.

## 5. Converting a document (the first document-to-software workflow)

The first conversion recommended by the addendum is the FIT Finder; the
first that slots into Empire Studio as built is **Brand-in-a-Box → Brand
Blueprint**. Neither can be done honestly without the file. When a file
lands in `content/source/`:

1. Read it end to end. In `scripts/build-register.mjs`, fill the asset's
   `original_document`, `version`, `product_status`, `intended_use`,
   `customer_problem`, `missing_information`, set `source_reviewed: true`,
   and run `node scripts/build-register.mjs`.
2. Reconstruct the method in the document's own terms and steps. For a
   generator, write it into `src/content/methodology.ts` (`instructions`),
   set `status: "source"` and bump `version`. For a calculator or scoring,
   write it as plain TypeScript with unit tests built from the document's
   own worked examples.
3. Flag anything ambiguous in `missing_information` instead of guessing.
4. Keep the PDF available as a downloadable resource where useful
   (worksheets, print workbooks), linked from the feature — not as the
   product itself.
