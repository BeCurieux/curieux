# M2 — Real classes and enrolments

## Goal

Replace the demo's classes, families and enrolments with real data, so a
business can set up its timetable, add families and enrol children.

## Decisions (confirmed with the product owner)

1. **Families belong to one organisation.** When Aqua House adds the Burrows
   family, that record is Aqua House's alone. A second provider has its own
   record for the same family. A parent account can belong to several
   families, one per provider, and the family app shows them together.
   Linking a family across providers is deferred (`DATA_MODEL.md` rule 7).
2. **Instructors see only the children in classes they teach.** Owners see
   every family and child in their organisation.
3. **Owners add families; parent invites come later.** The owner records the
   primary contact's name, email and phone on the family. Emailed invites
   need Resend and arrive in a later milestone. Seeded demo parents keep
   working.
4. **Real where built.** Classes, occurrences, families, children,
   enrolments and schedules come from the database. Absences, make-ups,
   vacancies, attendance and progress stay as the M1 demo overlay until
   M3–M5, applied only to the seeded Aqua House classes and children.

## Scope

### Business (owners)

- **Settings → Locations:** add and edit locations.
- **Settings → Programs & levels:** add programs, add levels in order.
- **Classes:** create and edit a recurring class (program, level, location,
  instructor, weekday, start time, duration, capacity); deactivate it.
  Creating a class schedules its next 12 weeks of occurrences.
- **Families:** list and search real families; add a family with its
  primary contact; add and edit children.
- **Enrolments:** enrol a child in a class from the class page; end an
  enrolment. A full class refuses new enrolments; a child can't be enrolled
  twice in the same class.
- **Settings → Activity:** the audit log of these changes.

### Family

- Home, Calendar and Kids show the children and classes they are really
  enrolled in.

### Instructor

- Home shows the classes they teach with each one's next occurrence; the
  class page shows its real roster.

## Rules and where they live

- Tenant integrity is enforced by the database: every tenant row carries
  `organisation_id`, and composite foreign keys stop a class from pointing at
  another organisation's location, level or instructor, or an enrolment from
  joining a child and class from different organisations.
- Capacity is enforced by a trigger that locks the class row, so two
  simultaneous enrolments can't both take the last place.
- Occurrences are generated by the database when a class is created or its
  schedule changes, in the location's timezone.
- Every insert, update and delete on the tenant tables writes an
  `audit_events` row with the acting user.

## Not in M2

- Parent invitations and self sign-up.
- Real absences, make-ups, vacancies, attendance or progress (M3–M5).
- Extending the 12-week occurrence window automatically (a scheduled job,
  before the pilot in M6).
- Instructor names on the family app (needs a name-only view of staff).
- CSV import (M6).

## Acceptance criteria

### Security (RLS)

- An owner reads and writes only their own organisation's locations,
  programs, levels, classes, occurrences, families, children, enrolments and
  audit events.
- An instructor reads the children and enrolments of classes they teach, and
  no others, and cannot write.
- A parent reads only their own family's children, enrolments, and the
  classes and occurrences those enrolments are in, and cannot write.
- A class can't reference another organisation's location, level or
  instructor; an enrolment can't cross organisations.
- A class can't be over-enrolled, even by two enrolments at once.

### Business path

1. Add a location, a program and a level.
2. Create a class; it shows 12 upcoming occurrences.
3. Add a family and a child.
4. Enrol the child; the class roster and enrolled count update.
5. A full class refuses another enrolment with a clear message.
6. End the enrolment; the roster updates.
7. Activity lists each of these changes and who made them.

### Family and instructor

- The Burrows family sees Ava's and Leo's real classes on Home, Calendar and
  Kids, and the M1 demo path still passes.
- Mia sees the classes she teaches and their real rosters; the M1
  instructor path still passes.
