# Kill-test candidates, second batch — merchants who photograph their own stock.
#
#   pnpm --silent screen killtest/candidates-makers.txt >> killtest/targets.txt
#
# `--silent` is not optional — see the note in candidates.txt.
#
# ------------------------------------------------------------------ why this
#
# The first batch screened 13 good · 24 workable, which clears thirty. It also
# came back with an empty mediocre-photography sample, and the brief is
# explicit that the renderer "must flatter mediocre product photography". A run
# across thirty studio catalogues tests the easy case thirty times and tells us
# nothing about the hard one.
#
# Two things were wrong, and only one of them is this file.
#
# The screener's photography test asked whether any product carried two images.
# That counts uploads, not photography — a maker who shoots four flat pictures
# on a phone scores identically to a studio session — so it now reads crop
# consistency and image size as well, and reports what it measured. Re-running
# the first batch through it will find hard candidates that the old flag missed,
# and that costs nothing but the screening time.
#
# The other thing wrong is the list. Every name in the first batch was a brand
# I could half-name from memory, and a brand at that size has usually paid a
# photographer at least once. This one is aimed at the other shape of merchant:
# small enough to shoot their own stock on a table by a window, established
# enough to have twenty products to merchandise. That second half is the hard
# constraint — most one-person makers will fail the product floor, so this list
# is long and its expected reject rate is much higher than the first.
#
# ---------------------------------------------------------------- provenance
#
# EVERY LINE HERE IS UNVERIFIED, on the same terms as the first batch. It was
# written with no outbound network — every storefront returns 000 through the
# egress proxy — so this is training-data recall, not a checked list. Some are
# gone, some were never on Shopify, some closed their feed. Screen first.
#
# What is *not* a guess is the shape being aimed at, and that is the part worth
# keeping if you replace half these names with better ones: makers, studios,
# single-operator shops, and small-batch food and drink. If you know ten of
# these yourself, yours are better than mine — the value here is the profile.
#
# --------------------------------------------------------------- the profile
#
#   · sells a thing they make, or a tight edit they chose by hand;
#   · 20-200 products, so there is something to select from;
#   · photographs it themselves, in daylight, against whatever was nearest;
#   · sells off Instagram, and has no developer.
#
# A store whose grid is visibly inconsistent — some products cropped square,
# some portrait, some on a white sweep and some on a wooden bench — is the one
# to keep. The screener will flag it POOR PHOTOGRAPHY. That is a reason to
# include it, not a defect, and it is the single most useful thing in the list.
#
# --------------------------------------------------------- the batch-1 overlap
#
# Three names below are commented out because they are already in
# `candidates.txt`: earlofeast.com, wolfandmoon.com, otiumberg.com. Written from
# memory, twice, they turned up in both lists — which is invisible here and
# fatal two commands later. `pnpm screen` reads one file and knows nothing about
# the other, so both runs emitted the same three lines, both were appended to
# `targets.txt`, and the kill test refused to start: `Duplicate targets. Thirty
# merchants means thirty merchants.` The whole point of that check is that
# thirty means thirty rather than twenty-seven counted generously, so it is
# right to refuse and the list is the thing to fix.
#
# The screener cannot fix this for you. It never reads the targets file, and
# giving it the ability to would mean it decides what is already in the run —
# which is the person's job, not the tool's.
